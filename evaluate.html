A store that runs

A knowledge base whose code is Scheme is not far from the old idea of a Lisp machine -- with the qualification first: only Scheme blocks evaluate today.

01

What evaluates, and where

Only Scheme blocks evaluate today. A library block in datum mode holds one definition per child block, and eval --under <library> evaluates an expression with those definitions in scope. The environment is the R6RS libraries and a small read view of the store; a library that asks for anything else is refused rather than quietly given less. The evaluation is a child process with a wall-clock limit, a memory limit and an output quota, and what it prints comes back in a field of the answer instead of mixed into it.

02

Evaluate at a point in history

Because the state is a reduction of the log, an evaluation can be asked for at a cut -- and it then runs the definitions as they stood at that point. Not a diff of the source, the behaviour: the old definition, called. The answer always reports the cut it actually used, so the run has a coordinate to be repeated from.

$ theourgia eval --under <library> '(f)'
(ok (values ("second version")) (working-view #f (("koou2buo" . 8))) ...)

$ theourgia eval --under <library> '(f)' --cut '(("koou2buo" . 7))'
(ok (values ("committed")) (working-view #f (("koou2buo" . 7))) ...)

The definition was changed between the two calls. The second asks for the earlier cut and gets the behaviour that was there then.

03

What the sandbox is given

The limits are arguments, with bounds: --timeout-ms between 1 and 60000, default 3000; --memory-bytes between 1 MiB and 2 GiB, default 256 MiB; --output-bytes between 128 and 1 MiB, default 65536. The output quota counts what the evaluation actually printed rather than what the framing made of it. A run that exceeds one is answered (error eval-limit (resource time|memory|output) (limit <n>) ...) -- which resource, and what the limit was.

04

What is not there yet

Evaluating a library against a writer's own uncommitted drafts is not something to lean on yet. --working exists and reports the view it used, but a draft over a definition block does not come into scope: measured, an expression that touches the drafted name fails as though the name had never been defined, while the same expression against the committed state answers. So running a branch in a scratchpad, and running several branches side by side to compare them, is a plan rather than a feature. What works today is evaluation against what is committed, at any cut.
